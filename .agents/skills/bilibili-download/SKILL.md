# B 站视频与音频下载

使用现有的 `yt-dlp` 下载，使用 `ffmpeg` 合并音视频或做用户明确要求的简单处理。不要为单次下载另造下载器。

## 下载流程

1. 检查 `yt-dlp` 是否可用；需要合并或处理时检查 `ffmpeg`。用户未指定保存位置时，保存到 `~/Downloads`。使用标题和 BV 号命名，避免覆盖已有文件。
2. 默认按用户要求下载单个视频，不跟随合集或播放列表。用户要最高画质时，先查询该视频实际可用格式，再选择可访问的最高视频流和音频流并合并为 MP4；不要臆测分辨率。用户已指定画质、视频或音频时，不重复询问。
3. 只有在用户明确指出某个已登录浏览器可用时，才用 `--cookies-from-browser <browser>` 读取其本机登录态。不要索要或输出密码、验证码或 Cookie；不要导出、保存或提交 Cookie 文件。
4. 仅下载当前账号有权访问的内容。若登录态、会员权限或站点风控阻止访问，说明实际限制并停止；不绕过付费限制或反爬保护，不自动安装第三方下载脚本。普通网络中断可让 `yt-dlp` 按默认策略重试，重复失败后报告错误。
5. 下载独立音频时优先保留来源音频编码。若用户要从已下载视频另提音轨，先检查音频编码，再用 `ffmpeg -map 0:a:0 -vn -c:a copy` 无损复制；目标容器不兼容时才转码，并说明这一点。
6. 只在用户要求时做裁切、转码、抠像等处理，并保留原始下载。竖屏裁切默认保留原背景；白色背景若已烘焙进画面，无法无损恢复透明通道。先说明透明格式的兼容性和文件体积取舍。
7. 保存到项目时，检查目标项目的 `AGENTS.md` 和 Git 状态，遵循其素材目录和提交规则。当前 `meme-workspace` 根仓库不存放独立素材库；素材应进入对应项目或 Skill 目录。不要自动推送。

## 常用命令

单视频，下载最高可用视频与音频并合并：

```bash
yt-dlp --no-playlist -f 'bv*+ba/b' --merge-output-format mp4 \
  -P "$DEST" -o '%(title)s [%(id)s].%(ext)s' "$URL"
```

仅当用户明确指定的浏览器里已有登录态时，在命令中加入 `--cookies-from-browser edge`（或对应浏览器名）。不要将该参数结果写入 Cookie 文件。

下载完成后用 `ffprobe` 核对文件是否可读、编码、分辨率、时长和大小；向用户提供实际保存路径，并简要说明可用画质或失败原因。
